CE-018 PROJECT CONTROLS AI ASSURANCE STARTER PACK
Version v1.0
=========================================================================

READ THIS FILE FIRST.

-------------------------------------------------------------------------
WHAT THIS PACK IS
-------------------------------------------------------------------------
A reusable set of Project Controls templates for running an AI-assisted
assurance task under control: bounded purpose, approved evidence, defined
tests, and a named human decision-maker.

Seventeen templates across four stages. Every template is supplied in two
forms in the same file:

  * a BLANK reusable version   - status: TEMPLATE - CONFIGURE BEFORE USE
  * a COMPLETED worked example - status: ISSUED FOR PROJECT MANAGER
                                 REVIEW (IFR) - NOT APPROVED

The blank and worked versions are always held on separate worksheets or
under separate headings. Never issue a blank template as a record, and
never treat the worked example as an approved position on your project.

-------------------------------------------------------------------------
BOUNDARY - READ BEFORE USE
-------------------------------------------------------------------------
The templates support controlled Project Controls assurance. They do not
provide legal advice, certify NEC4 compliance or transfer contractual
authority to AI. Users must configure the templates to their contract,
governance, data classification and named decision roles.

-------------------------------------------------------------------------
FICTIONAL DEMONSTRATION DATA
-------------------------------------------------------------------------
Every worked example in this pack is Fictional Demonstration Data.

The project (Westbridge Station Access and Enabling Works), the event
(CE-018 - Restricted access to the Platform 4 worksite), the organisations
and all named individuals are invented for demonstration. The clause
references, response periods and control definitions are CONFIGURED DEMO
CONTROLS, not a statement of NEC4 or legal compliance.

In live use, replace them with your executed contract, Contract Data,
Scope and amendments.

-------------------------------------------------------------------------
RETAINED HUMAN AUTHORITY
-------------------------------------------------------------------------
An assistant may extract, link, compare, reconcile, cite, flag and prepare
review material.

An assistant must not decide entitlement, assess or accept a quotation,
issue a contractual communication, instruct work or implement a change.

In the CE-018 worked example, Elena Brooks, NEC4 Project Manager, retains
every contractual decision. On your project, name the equivalent
accountable role before the first assisted run.

WHAT IS IN THIS ZIP
-------------------------------------------------------------------------
At the root:

  README_FIRST.txt                         This file.
  CE018_Starter_Pack_User_Guide.docx       How to run a bounded, governed
                                           and tested assisted task in
                                           ten steps.
  CE018_Starter_Pack_Quick_Start_Guide.pdf Two-page summary.

                                           stage, format, owner, status
                                           and worked-example source.

Four stage folders:

  01 Control uncertainty   SP-01, SP-02
     Define one bounded task and record what is not yet known.

  02 Govern AI use         SP-03 to SP-09
     Set the project rules, approved sources, briefing, written task
     instruction, workspace configuration and authority route.

  03 Test the output       SP-10 to SP-14
     Register the evidence, run the four tests, score them, run the
     configured NEC4 controls and report the exceptions.

  04 Decide and learn      SP-15 to SP-17
     Record the human decision, the corrective actions and retests, and
     what the run proved.

-------------------------------------------------------------------------
HOW TO USE THE PACK
-------------------------------------------------------------------------
1. Read the User Guide, or the Quick Start Guide if you are short of time.
2. Work the stages in order, 01 to 04. Each stage produces the controlled
   inputs the next stage needs.
3. Start with ONE bounded, real Project Controls decision. Complete one
   controlled review before extending the method.
4. Configure every template to your own contract, governance, data
   classification and named roles before the first live run.
5. Keep the completed records. They are the audit trail.

-------------------------------------------------------------------------
A NOTE ON THE SCORECARD
-------------------------------------------------------------------------
CE018_SP12_Test_and_Acceptance_Scorecard.xlsx is formula-driven. Totals,
critical-failure detection and route logic calculate automatically. Open
it in Excel and allow calculation. Do not overwrite the formula cells.

Scoring: 2 = pass; 1 = bounded limitation; 0 = critical failure.
Any score of 0 determines the route regardless of the total.
